The launcher makes one verified local checkpoint copy. By default it chooses `/tmp` or `/dev/shm` with sufficient free space; set POLICY_LOCAL_CACHE to override. It then loads two batches: eight processes concurrently, one per GPU, followed by the second eight only after the first batch is ready. The existing port mapping is preserved (even server IDs first, odd IDs second). It waits for each process's new ready log marker before a real WebSocket status RPC, so model loading produces BATCH_LOADING progress rather than repeated expected connection-refused messages. All 16 RPC checks must pass before ALL_HELIOS_SERVERS_READY. Parallel loading raises peak host RAM demand compared with serial loading; the eight-GPU loading throughput must be measured on the cloud allocation. Model weights consume 12.13 GB; a 14 GiB free-space guard is applied.

Stop the previous cloud job before resubmission. The EVAL_RUN_ID is unchanged because the model and evaluation protocol are unchanged; the shared campaign lock prevents two launches from owning this campaign simultaneously. Each server retains a 900-second startup deadline; child failures abort the group and clean up its own processes.

The first-request timeout starts when a policy becomes ready. Status/health checks do not count as activity. Valid reset, action and observation requests do count; an in-flight request prevents idle shutdown. Normal idle exit of one server does not kill the remaining servers. Model/server failures stop the group. After all policies exit, the shared CPU text service exits too.

## Train/inference contract

- Same trained Helios network and configuration: history [16,2,1], two episode anchors, 14D joint action/proprio.
- Same normalization snapshot, text prompt, T5 tokenizer/encoder, 128-token context and FastWAM context-mask semantics. Missing evaluation instructions are encoded once by a shared CPU T5 service.
- Wrist images above the head image, RGB mosaic 384×320. Every executed action step supplies an observation; RGB is sampled every four steps. History uses real observations only and resets per episode.
- Horizon/replanning interval 16, 10 action-denoising steps (updated at user request), BF16. POLICY_INFERENCE_STEPS defaults to 10 in both launchers and is recorded in the immutable campaign identity. Condition augmentation remains recorded as true in the training contract; inference uses clean observations, as implemented by the trained model's inference method.
- No Transformer KV persists between decisions. Sampled RGB history is retained and its causal VAE prefix is encoded at each decision.
